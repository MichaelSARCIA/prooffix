Why this is different

Most AI review tools stop at suggesting a fix. ProofFix treats a suggestion as a claim that has to be checked.

1

Prove

Write a test that fails, so the bug is demonstrated — not asserted.

2

Fix

Apply the smallest patch, then run the full suite to confirm nothing else broke.

3

Coach

Explain why it happened and how to avoid the same mistake next time.

Run live in IBM Bob

Each stage below ran as its own IBM Bob mode, with access limited to what that job needed — read-only for review, edit-and-run for fixes, markdown-only for the report.

What it found

Five bugs were deliberately planted in a small shopping-cart module. Click a finding to see the proof, the fix, and the lesson.

F-01 Discount codes evaluated with eval() critical 28×
Risk
A crafted discount-code string could execute arbitrary code inside the server process.
Proof
An injected payload triggered evaluation before the fix — confirmed with a failing test.
Fix
Replaced eval() with a plain dictionary lookup.
Lesson
Never pass user-supplied strings into eval or exec; use a lookup table instead.
F-02 Off-by-one error drops the last item from every total high 40×
Risk
Every multi-item cart under-charged by the price of its last item; single-item carts totalled zero.
Proof
A two-item cart returned the wrong subtotal before the fix.
Fix
Replaced manual index arithmetic with a plain sum over all items.
Lesson
Prefer iterating a collection directly over hand-written index ranges.
F-03 Zero and negative quantities silently accepted high 40×
Risk
A quantity of zero or less could insert ghost items or push stock counts negative.
Proof
Adding an item with quantity 0 completed without error before the fix.
Fix
Added a validation guard that raises on non-positive quantities.
Lesson
Validate domain rules at the point of entry, not downstream.
F-04 Money stored and summed as float medium 30×
Risk
Floating-point rounding drift accumulates across line items, producing penny-level errors.
Proof
Ten items at $0.10 summed to a value slightly off $1.00 before the fix.
Fix
Switched prices and rates to Decimal throughout.
Lesson
Never use float for currency; use a fixed-point type from the start.
F-05 Duplicated branches in the total calculation medium 30×
Risk
Two identical branches meant a future change to the discount formula could be made in one place and missed in the other.
Proof
A type-hint check confirmed the method hadn't been reconciled with the rest of the codebase.
Fix
Collapsed the duplicated branches into a single, direct calculation.
Lesson
When two branches are identical, extract the shared logic instead of guarding around it.

The same run also surfaced three additional real issues beyond these five — a related empty-cart edge case, an unguarded negative-quantity update, and a float/Decimal mismatch in the discount table.
